**Unified Agent Tuning (`internal/agentcfg`)**

- `agentcfg` is the single owner of the harness-neutral model/effort surface and of the mapping down to each harness's native mechanism (claude/copilot `--effort`, codex `-m` + `-c model_reasoning_effort`, grok `--reasoning-effort`, pi `--thinking`, opencode's session-message `model`/`variant`, acpx `--model` for `cursor`/`acp:<target>`). Add a harness there, not in an adapter or in eval. `rovodev` and `antigravity` are deliberately declared unmappable, so a request for them is a config error rather than a flag that is silently ignored.
- `agent.NewWithOptions` is the one funnel: it validates `Options.Profile` and splices the mapped args after the operator's raw `agent_args_override` args, so both the pipeline (`cfg.AgentProfileFor`) and eval replay (`Candidate.Profile()`) reach every harness by the same path. Never re-derive a model or effort flag at a call site.
- Precedence is fixed: a raw `agent_args_override` flag that already pins a knob natively wins and the mapped value is not emitted, which is what keeps every pre-`agent_config` configuration byte-identical and stops a harness receiving one knob twice. `agent_config` is global-only for the same reason as `agent_args_override`.
- Opt-in Pi run pins (`axi run` / `rerun` `--model`, `--effort`) resolve in `config/pi_profile.go`, persist immutably in `runs.pi_profile`, and are applied before agent construction on launch and recovery. Raw selection flags conflict at creation; later raw/role/global model changes cannot replace a run pin. Unpinned runs retain the precedence above. Semantics owner: `docs/src/content/docs/reference/global-config.md` (Per-run Pi profiles); regressions: `*_pi_profile*` / `pi_profile_test.go` in config, db, daemon, CLI and e2e.
- Eval candidates are `agent,model=<model>[,effort=<level>]` (the previous `agent+model` spelling is refused with a migration message), effort is part of the persisted candidate identity, and `agentNeutralGlobalConfig` strips `agent`, `agent_args_override`, and `agent_config` so a replay never inherits the capturing machine's pins.
- Keep eval replay identity comparison centralized in `agentcfg.ServedMatchesRequested`; do not compare an adapter's reported model directly at call sites. The user-facing normalization semantics and candidate guidance live in [`docs/src/content/docs/reference/eval.md`](../../../docs/src/content/docs/reference/eval.md).
- Regressions: `internal/agentcfg`, `internal/agent/profile_test.go`, `internal/config/config_agent_config_test.go`, `internal/daemon/pipeline_agent_profile_test.go`, `TestParseCandidate*`, `TestReplayPinsCandidateModelAndEffortOnTheHarness`, `TestCaptureStripsEveryHarnessPinFromThePinnedConfig`, `TestServedMatchesRequested`, `TestReplayPiModelIdentityComparison`.

**Quota-Auto Agent Selection (`internal/quota`)**

- `agent: quota-auto` plus the global-only `agent_candidates` list is the one selection mode that chooses the pipeline harness per run and per step instead of pinning it. Both keys are global-only for the same reason as `agent_config`: they decide whose credentials and whose paid allowance a run spends. `config.resolveQuotaAutoAgent` resolves the harness half of eligibility offline (installed binary) and keeps the operator's order in `cfg.Agents`; `cfg.QuotaAuto` records the resolved mode, and a trusted repository `agent` pin outranks it.
- `quota.Select` applies the three gates against one `quota-axi models --json` read: eligibility (provider fresh and measurable), reasoning-class fit (`quota.StepClass` is the policy; the attestation is the provider's catalog entries, or the pinned `agent_config` model's own entry, never `agent_config` effort), runway versus the step's configured ceiling (`agent_timeout` / `review_agent_timeout` / `test_agent_timeout` via `quota.Budgets`). Ranking is quota-axi's own `spendPriority`, then remaining percent, then runway, then list order; a signal the tool could not compute never outranks one it did.
- `daemon.quotaAutoPipelineAgent` builds the run: the selected harness leads the same fallback chain every pinned run uses (`newAgentChain`), and `SwitchingAgent.Reassess` is wired as the executor's step-boundary hook (`Executor.SetStepBoundaryFunc`) because a step boundary is the only place a harness may change - within a step the executor reuses one delegate across review rounds and fix turns, where a swap would drop the native session. A harness that still passes every gate is KEPT; a switch is reserved for one that stopped being viable, and it closes the harness it replaced. `startStep` skips the reassessment of the step the opening selection was just made for, one-shot, so a restart of that step is reassessed normally.
- Fail-closed rules: run start refuses to start with no eligible candidate (`*NoCandidateError`, one line per candidate, `quota.Record.EvidencePayload` bounded); a boundary KEEPS the harness in use when the evidence cannot be read at all (a vanished tool must not strand a run) but fails the run when every candidate is refused; under `disable_project_settings` a switch to an unverified harness is refused, because construction-time `EnsureGateNeutralized` never sees a harness that arrives later.
- `SwitchingAgent.SupportsSessionProvider` answers for the whole candidate SET rather than the harness in use, so `validateRecoveredSessionProviders` cannot refuse a recovered run whose recorded session belongs to a candidate quota may route back to, and `SupportsSessionResume`/`ReportsAgentAttempts`/`NeutralizesGateInstructions` mirror the harness in use.
- Decisions are appended to `run_agent_selections` (`db.RecordAgentSelection`, JSON from `quota.Record.EvidencePayload`, best-effort like other run state) at run start and on every switch; a kept boundary records nothing. Reading routing back is `db.ListAgentSelections`.
- Regressions: `internal/quota` (parse, gates, ranking, keep/switch, payload), `internal/config/config_quota_test.go`, `internal/daemon/quota_agent_test.go`, `internal/pipeline/executor_step_boundary_test.go`, `internal/db/agent_selection_test.go`, e2e `TestQuotaAutoRun_RoutesToTheBetterStandingCandidate` and `TestQuotaAutoRun_LiveEvidencePicksTheBetterStandingCandidate`.

**Per-Run Pi Profile Pin**

- A per-run Pi pin (`axi run` / `rerun` `--model`/`--effort`) is immutable once the run exists (`runs.pi_profile`, plus an immutability trigger) and must be fully validated **before** it supersedes an active validation: `startRunWithIntentSourceLocked` resolves it against global `agent`/`review_agents`/`agent_args_override.pi` and re-checks the merged trusted default-branch `agent` selection (`ResolvePiProfile`, `validatePiProfileAgentsBeforeCancel`), while the post-merge `ValidatePiProfileAgents`/`ApplyPiProfile` pass at worktree setup and `ApplyPiProfile` in `loadRecoveredConfig` remain the enforcement after cancellation. User semantics are owned by `docs/src/content/docs/reference/global-config.md` (Per-run Pi profiles). Regressions: `internal/config/pi_profile_test.go`, `internal/daemon/pi_profile_test.go` (`TestPiProfileInvalidLaunchDoesNotSupersedeActiveRun`, `TestPiProfileTrustedRepoAgentOverrideDoesNotSupersedeActiveRun`, `TestPiProfileRecoveryUsesPersistedPinAndLegacyUsesLiveConfig`), `internal/db/pi_profile_test.go`, `internal/cli/pi_profile_test.go`, e2e `TestPiRunProfileSurvivesGlobalChangesAcrossEveryDuty`.
