**Context, Concurrency, and Processes**

- Thread `context.Context` through long-running, subprocess, and networked work; prefer `exec.CommandContext`; use derived contexts and timeouts for cleanup and HTTP calls.
- Route every long-lived subprocess spawned for a cancellable step or agent invocation through the appropriate `shellenv` lifecycle configurator. Agents and other subprocesses use `ConfigureShellCommand`: it creates a process-tree boundary and installs `cmd.Cancel` to kill the whole tree, so grandchildren (test workers, build watchers) cannot outlive cancellation and hold the next run's worktree locked. Repository `commands.*` and custom gates use `ConfigureCooperativeShellCommand`: on Windows it sends targeted `CTRL_BREAK`, preserves up to a three-second cleanup window, then retains the same forced Job Object fallback. Regressions: `TestConfigureCooperativeShellCommandCancelAllowsCleanup`, `TestConfigureCooperativeShellCommandCancelForcesNonCooperatingTree`.
- `cmd.Cancel` covers only cancellation; on clean exit or error the group is not reaped, and leaked grandchildren accumulate until the OS OOM-kills the daemon (surfacing as `daemon crashed during execution` with no stack trace). Use `shellenv.RunShellCommand` / `OutputShellCommand` / `CombinedOutputShellCommand` for one-shot commands, or `StartShellCommand` plus `TerminateShellCommandGroup` when handling pipes manually; the helper doc comments in `internal/shellenv` own the details. `ConfigureShellCommand` also installs a 5s `cmd.WaitDelay` backstop so a grandchild holding an inherited pipe cannot wedge `cmd.Wait` forever. For Claude, Codex, and Pi, a cleanly exited agent's completed result remains usable when that backstop closes an inherited pipe; without a completed result, the parse failure is retained and reports whether a result event arrived. Claude also stops a process still open `claudeResultGrace` after its completed result (background work holds print mode open); a `RequireCompletedChildren` turn fails there and never counts that result. Regressions: `TestClaudeAgent_BackgroundWorkAfterResult`, `TestNativeAgents_FinishedResultSurvivesEscapedStdoutHolder`, `TestNativeAgents_UnfinishedRunKeepsParseErrorOverWaitDelay`, `TestCodexEmptyResultEventIsReportedAsReceived`, `TestCodexAgent_Run_ReapsLeakedGrandchildOnCleanExit`, `TestRunShellCommandWithEnv_ReapsGrandchildOnCleanExit`, `TestTerminateShellCommandGroup_*`.
- `internal/procreap` catches descendants that escape process groups by matching their cwd to a run's worktree or evidence directory. Its package and `Options` comments own the matching boundary, protected processes, signal escalation, and caller obligations for scoped sweeps. Every site that removes a run worktree sweeps it first through `procreap.SweepRunWorktree(s)` (run cleanup and setup failure via `RunManager.removeRunWorktree`, startup cleanup, eject); the unscoped worktree sweep in `recoverOnStartup` keeps the `orphanProcessMinAge` floor. Evidence callers, retention sequencing, and their regressions are owned by [test-evidence-storage](../test-evidence-storage/SKILL.md). All best effort. Windows uses job objects to contain the whole tree, so the platform layer reports an empty table. Regressions: `internal/procreap`, `TestSweepOrphanRunProcessesReapsFinishedRunAndSparesActiveOne`, `TestSweepRunWorktreeProcessesReapsLeakedChildAtRunCleanup`, `TestTerminateShellCommandGroup_AsksBeforeKilling`, `TestTerminateShellCommandGroup_EscalatesWhenSIGTERMIsIgnored`.
- On Windows the daemon runs console-less (#1653). The managed task launches `no-mistakes.exe daemon run --root <root>` directly. Its XML definition sets `DisallowStartIfOnBatteries` and `StopIfGoingOnBatteries` to `false` and `ExecutionTimeLimit` to `PT0S`, because Task Scheduler's short-job defaults otherwise stop a long-running daemon on battery and after a fixed runtime; keep those settings. The binary embeds an application manifest with `consoleAllocationPolicy=detached`, so Windows 11 24H2 / Server 2025 (build 26100) and later allocate no console when there is none to inherit, while a terminal, hook, or agent still shares its console. The manifest is owned by `internal/winres`, which renders `cmd/no-mistakes/rsrc_windows_{amd64,arm64}.syso` (`make winres`; `make lint` and a go test fail on drift); never commit an object from another tool. Older builds ignore the manifest, so `daemon.PrepareRunStdio`, the first thing `daemon run` does (and only `daemon run`, never another entry point such as the log-sink or a CLI sharing a hook's or agent's console), frees a console only this process is attached to (a terminal's shared console stays) and points stdout/stderr without a usable handle (NULL under the manifest start, or the released console) at the bootstrap log, as the detached start path does. The policy also overrides `CREATE_NEW_CONSOLE`, so the cooperative-command helper (the same binary) allocates its private console itself, without a window, before starting its target (`ensureWindowsCooperativeConsole`), or `CTRL_BREAK` never reaches the target. Keep the task's process the daemon itself: a launcher or `conhost --headless` wrapper breaks `schtasks /End`, `inspectWindowsManagedDaemon`, and the argv scans in `collision.go`. Regressions: `internal/winres` (`TestObjectCarriesOnlyTheManifest`, `TestCommittedObjectsMatchGenerator`, `TestNoMistakesExecutableCarriesExactlyTheManifest`, `TestNoMistakesGetsNoConsoleFromAConsolelessParent`), `TestConfigureCooperativeShellCommandCancelAllowsCleanupWithShippedHelper`, `TestReleaseSoleConsoleFreesOnlyAConsoleOfItsOwn`, `TestPrepareRunStdio*`, `TestRunPreparesDaemonStdioBeforeTheDaemonRuns`, `TestOnlyDaemonRunPreparesDaemonStdio`, `TestRenderWindowsTaskXMLScopesLogonTriggerToInstallingUser`, `TestRenderWindowsTaskXMLAllowsLongRunningOnBattery`, `TestInstallWindowsTaskRegistersUserScopedLogonTask`.
- A console-less process - the daemon, or a CLI started without a console (`Start-Process` without `-NoNewWindow`, a double-click) - gives every console child a window of its own, so route every console child through `winproc.Harden(cmd)` (no-op elsewhere, idempotent, preserves existing creation flags) or a console window flashes per child (#287). `shellenv.ConfigureShellCommand` already calls it; one-shot commands built directly must call it themselves. Regressions: `TestHarden*` in `internal/winproc`.
- Protect shared mutable state with the standard sync/atomic tools, and be explicit about ownership and cleanup of goroutines, worktrees, temp dirs, and channels.
